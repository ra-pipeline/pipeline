7 minfracmaxbw=None, samebb=None, phasesnr=None, intphasesnr=None, intphasesnrmin=None, 

8 phaseupmaxsolint=None, bwedgefrac=None, hm_nantennas=None, maxfracflagged=None, combine=None, 

9 refant=None, minblperant=None, minsnr=None, unregister_existing=None): 

10 """Compute phase calibration spw map and per spw phase offsets. 

11 

12 :func:`~pipeline.hifa.cli.hifa_spwphaseup` computes the spw map for phase calibration, and derives 

13 phase offsets as a function of spectral window using high signal-to-noise 

14 calibration observations. Previous calibrations are applied on the fly. 

15 

16 :func:`~pipeline.hifa.cli.hifa_spwphaseup` performs two functions: 

17 

18 .. figure:: /figures/PL2025_lowSNR_spwphaseup_v1.png 

19 :width: 60% 

20 :alt: Logic flowchart for spw phase-up strategy 

21 

22 Logic flowchart for determining the temporal gain strategy. Extends 

23 phase-up mapping/combine, ``solint`` and ``gaintype`` calculation to 

24 all intents except the Polarization calibrator. 

25 

26 - Determines the spectral window mapping or combination mode, gaintype and 

27 solint, for each independent bandpass, amplitude, diffgain, phase and check 

28 source, to use when solving the phaseup (phase as a function of time) in 

29 subsequent stages (mapping mode and gaintype in :func:`~pipeline.hifa.cli.hifa_gfluxscaleflag`, all 

30 parameters for :func:`~pipeline.hifa.cli.hifa_gfluxscale` and :func:`~pipeline.hifa.cli.hifa_timegaincal`), and when applying those solutions 

31 to targets. 

32 

33 - Computes the per-spectral-window phase offset table that will be applied 

34 to the data to remove mean phase differences between the spectral windows. 

35 

36 If ``hm_spwmapmode='auto'``, then the spectral window map is computed for 

37 each SpectralSpec and each calibrator source, using the following algorithm: 

38 

39 - Estimate the per-spectral-window (spw) signal-to-noise ratio based on 

40 catalog flux densities, Tsys, number of antennas, and integration scan time. 

41 These estimates are shown in the weblog. 

42 

43 - Compute the per-spw signal-to-noise for each above mentioned intent based 

44 on an temporary phaseup gain calibration using solint ``inf`` for the PHASE 

45 and CHECK intents, and ``int`` otherwise. These computed signal-to-noise 

46 values override the use of the estimated values unless none are found. 

47 

48 - If SNR calculation fails, then subsequent heuristics are skipped, warnings 

49 printed, and mapping falls back to narrow-to-wide. 

50 

51 - If the signal-to-noise of all spws is greater than ``phasesnr`` for a 

52 PHASE or CHECK intent, or greater than ``intphasesnr`` for the other 

53 intents, then if SNR is high enough to keep solint='int', then 

54 no mapping is used (each spw is used to calibrate itself). If the calculated 

55 solint is >'int' then mapping and combine are attempted, to favor a 

56 short solint over keeping the spws independent. 

57 

58 - If the signal-to-noise of only some spws are greater than the value of 

59 ``phasesnr`` for the PHASE or CHECK intent, or ``intphasesnr`` for the 

60 other intents, then each lower-SNR spw is mapped to the highest SNR spw 

61 in the same SpectralSpec. 

62 

63 - If all spws have low SNR (or all spws in a given SpectraSpec for 

64 multi-SpectralSpec observations), then spws are combined. 

65 

66 - The time solint is calculated and stored for phaseup in subsequent stages. 

67 If ``hm_spwmapmode`` is not ``'combine'`` then there is at least one high 

68 signal-to-noise spw, then by definition that has a solint of ``'int'``. For 

69 ``hm_spwmapmode='combine'``, the computed signal-to-noise is used 

70 in conjunction with ``phasesnr`` for the phase and check intents, or 

71 ``intphasesnr`` for the other intents. First the gaintype is changed 

72 from 'G' to 'T' (combine polarization) and thereafter solint is increased 

73 from ``'int'`` up to the limits of 1/2 scan for the phase or check intent, or 

74 to the input ``maxphaseupsolint`` for the other intents 

75 

76 - If ``hm_spwmapmode`` is ``'combine'`` and no SNRs are found, the PHASE and CHECK 

77 intents will default to a solint of 1/4 scan. 

78 

79 - If the intent is AMPLITUDE, and gaintype was changed from 'G' to 'T', 

80 the signal-to-noise required to be met before increasing solint above ``'int'`` 

81 is reduced to ``intphasesnrmin``. 

82 

83 If ``hm_spwmapmode='combine'``, :func:`~pipeline.hifa.cli.hifa_spwphaseup` maps all the science windows 

84 to a single science spectral window. For example, if the list of science 

85 spectral windows is ``[9, 11, 13, 15]`` then all the science spectral windows 

86 in the data will be combined and mapped to the science window ``9`` in the 

87 combined phase vs time calibration table. 

88 

89 If ``hm_spwmapmode='simple'``, a mapping from narrow science to wider 

90 science spectral windows is computed using the following algorithm: 

91 

92 - Construct a list of the bandwidths of all the science spectral windows. 

93 

94 - Determine the maximum bandwidth in this list as ``maxbandwidth``. 

95 

96 - For each science spectral window with bandwidth less than ``maxbandwidth``, 

97 construct a list of spectral windows with bandwidths greater than 

98 ``minfracmaxbw * maxbandwidth``, then select the spectral window in this 

99 list whose band center most closely matches the band center of the narrow 

100 spectral window, and preferentially match within the same baseband if 

101 ``samebb=True``. 

102 

103 If ``hm_spwmapmode='default'``, the spw mapping is assumed to be one to one. 

104 

105 

106 After determining the combine and mapping parameters and time solints, 

107 phase offsets per spectral window are determined by computing a phase only gain 

108 calibration on the selected data, normally the high signal-to-noise bandpass 

109 calibrator observations, using the solution interval 'inf'. 

110 

111 At the end of the task the spectral window map, solint and gaintype along 

112 with the phase offset calibration table(s) in the pipeline are stored in 

113 the context for use by later tasks. 

114 

115 Finally, the SNR of the calibration solutions are inspected and if the median 

116 value on a per-spw basis does not reach specific thresholds, a warning is 

117 issued with a reduced QA score. For PHASE intent, blue, yellow, and red QA 

118 result if the achieved SNR is less than 0.75, 0.5, and 0.33 times ``phasesnr``, 

119 respectively. For BANDPASS, AMPLITUDE, and DIFFGAIN intent, QA messages are 

120 based on 0.75, 0.5, and 0.33 times ``intphasesnr`` (unless ``intphasesnrmin`` 

121 was used for BANDPASS or AMPLITUDE). Finally, for CHECK intent the QA score 

122 is always blue, but scales depending on achieved SNR relative to ``phasesnr``. 

123 

124 **Phase decoherence assessment** 

125 

126 Using the bandpass phase-up solutions from :func:`~pipeline.hifa.cli.hifa_bandpass`, the baseline-based phase RMS is reconstructed 

127 for each antenna relative to the reference antenna. For each baseline the phase RMS is calculated over 

128 the entire bandpass scan (total-time) and also over a period equal to the phase referencing cycle time. 

129 The median phase RMS of all baselines longer than the 80th percentile is reported in the WebLog table. 

130 

131 Outlier antennas (phase RMS > 180 deg, or > 4 x MAD + median when median > 50 deg, or > max(6 x MAD + median, 

132 2 x median) when median <= 50 deg) are identified and shown as semi-transparent symbols in the plot. When 

133 outliers are found above 50 deg, a reassessment is made excluding them. 

134 

135 .. figure:: /figures/hifa_spwphaseup_phasedeco_PL2022.png 

136 :width: 60% 

137 :alt: Phase decoherence plots 

138 

139 Example phase decoherence plots (phase RMS vs. baseline length). Semi-transparent 

140 points indicate excluded outlier antennas. Horizontal coloured lines show the 

141 decoherence thresholds at 30 deg, 50 deg, and 70 deg. 

142 

143 Notes: 

144 QA scores for phase decoherence: 

145 

146 - Phase RMS < 30 deg (excellent stability): QA = 1.0 (or 0.9 if outlier antennas detected). 

147 - Phase RMS 30-50 deg (good stability): QA = 0.9. 

148 - Phase RMS 50-70 deg (notably elevated): QA between 0.3 and 0.5. 

149 - Phase RMS > 70 deg (poor stability): QA between 0.0 and 0.3. 

150 

151 Phase RMS of 30 deg, 50 deg, and 70 deg correspond to flux decoherence of ~13%, ~32%, and ~53% respectively. 

152 These thresholds are shown as coloured horizontal lines in the phase decoherence plots. 

153 

154 The overall stage score is the lowest of the gain calibration QA and the phase decoherence QA. 

155 

156 Examples: 

157 1. Compute the default spectral window map and the per spectral window phase offsets: 

158 

159 >>> hifa_spwphaseup() 

160 

161 2. Compute the default spectral window map and the per spectral window phase offsets set the spectral 

162 window mapping mode to 'combine': 

163 

164 >>> hifa_spwphaseup(hm_spwmapmode='combine') 

165 

166 """
