15 """This task attempts to perform self-calibration on all science targets for which the  

16 estimated SNR per-EB per-antenna is >3. The task channels-averages the science data to  

17 15.625 MHz, flags line channels (from :func:`~pipeline.hif.cli.hif_findcont`), splits  

18 each source into a temporary MS, and then iterates through a series of gain solution  

19 intervals. In the event that self-calibration succeeds for a given target, the successful  

20 self-calibration solutions are applied to that target. For sources where self-calibration  

21 does not succeed, or for which self-calibration is not attempted due to the estimated  

22 SNR per-EB per-antenna being too low, no solutions are applied. 

23 

24 **Handling of Data and Imaging During hif_selfcal** 

25 

26 The pipeline tracks multiple data type labels to manage regular and self-calibrated data: 

27 

28 - ``REGCAL_CONTLINE_SCIENCE``: data with regular calibrations applied (``DATA`` column of 

29 ``*_targets.ms``). 

30 - ``SELFCAL_CONTLINE_SCIENCE``: data with self-calibration solutions applied (``CORRECTED`` 

31 column of ``*_targets.ms``). 

32 - ``REGCAL_LINE_SCIENCE`` / ``SELFCAL_LINE_SCIENCE``: equivalent line (continuum-subtracted) 

33 datatypes in ``*_targets_line.ms``. 

34 

35 At the beginning of this task, lines found by :func:`~pipeline.hif.cli.hif_findcont` (i.e.,  

36 the complement of the channel ranges found for continuum) are flagged, the data for each  

37 science target are split from the ``REGCAL_CONTLINE_SCIENCE`` column into temporary individual  

38 MS files with channels averaged to 15.625 MHz, and the original data is reverted to its  

39 pre-line flagging state. The task then uses these averaged, per-source temporary MS files  

40 for all imaging and calibration during the self-calibration process. If self-calibration  

41 is successful for a given science target, the solutions are applied to both the calibrated  

42 visibility data labeled as ``REGCAL_CONTLINE_SCIENCE`` and ``REGCAL_LINE_SCIENCE`` and stored  

43 in the ``CORRECTED`` columns of :file:`*_targets.ms` and :file:`*_targets_line.ms`, 

44 respectively. 

45 

46 All images generated as a part of :func:`~pipeline.hif.cli.hif_selfcal` are made from all  

47 SPWs for a given source and use ``robust=0.5`` along with auto-masking to define the mask  

48 during the cleaning process. The thresholds cleaned to, however, vary over the course of the  

49 self-calibration process and are described further below. 

50 

51 **Self-calibration Workflow** 

52 

53 :func:`~pipeline.hif.cli.hif_selfcal` starts by making a dirty image of each source to be  

54 self-calibrated and follows with a cleaned initial image with a threshold determined by in  

55 the same way as is done for :func:`~pipeline.hif.cli.hif_makeimages` (cont), using the  

56 predicted rms noise and a dynamic range correction factor. This initial image is used to  

57 assess whether there is sufficient SNR per-EB per-antenna and per-sub-field in the case of  

58 mosaics to attempt self-calibration and also to set the thresholds for each successive  

59 iteration of self-calibration (described further in the next section). 

60 

61 The task will then attempt self-calibration of all science targets that were deemed to  

62 have sufficient signal (SNR per-EB per-antenna >3) to attempt the process. For each such  

63 target, the task will loop through the list of solution intervals to attempt and perform  

64 the following operations: 

65 

66 1. Generate a "pre" image of the data, with all calibrations, including previous  

67 self-calibration solution intervals when this is not the first iteration of  

68 self-calibration, applied. The clean threshold used is described below. The model  

69 generated by this imaging process is saved in the ``MODEL`` column. 

70 2. Use the model generated in the previous step, placed in the ``MODEL`` column, along  

71 with the :func:`~casatasks.calibration.gaincal` CASA task to calculate gain solutions over  

72 the solution interval specified for this iteration. These solutions are applied to the  

73 science target. 

74 3. Generate a "post" image of the data, with the gain solutions from this interval of  

75 self-calibration applied. The clean threshold used is *exactly* the same as the  

76 threshold used for the "pre" image of the same solution interval. 

77 4. Evaluate the success of the gain solutions from this solution interval at improving  

78 the calibration of the data, discussed further in a subsequent section. 

79 5. If the gain solutions are deemed to have improved the calibration for this science  

80 target, move on to the next solution interval and repeat from step 1, or end  

81 self-calibration for this target if there are no further solution intervals to  

82 attempt. If the gain solutions, however, do not improve the calibration of the  

83 target then the calibration is reverted to its state prior to this iteration. 

84 

85 Once these iterations have been completed for each science target for which  

86 self-calibration was to be attempted, a final image is made with a clean threshold set  

87 by the minimum of 3x the rms determined from the final successful self-calibration  

88 iteration for that source and the clean threshold used to make the initial image prior  

89 to self-calibration. The latter is included to ensure that the final, self-calibrated  

90 image is always cleaned at least as deep as the initial image. 

91 

92 **Solution Intervals and Thresholds** 

93 

94 The self-calibration solution intervals to attempt and the thresholds to clean to for each of 

95 those solution intervals are calculated in advance of the self-calibration process. 

96 :func:`~pipeline.hif.cli.hif_selfcal` will start by cleaning relatively shallowly and with long 

97 solution intervals for gain calibration, but will decrease both the solution intervals and 

98 clean depths with each successive iteration. 

99 

100 The first solution interval, dubbed ``inf_EB``, is always set to use ``combine='scan'``, 

101 ``solint='inf'``, and ``gaintype='G'`` i.e. it is calculated over an entire EB, with separate 

102 solutions for each EB if multiple EBs are present. This first solution interval initially 

103 attempts to calculate solutions per-polarization and per-spw, but will also test whether using 

104 either a spw-map to map some spws to others with better solutions or ``combine='scan,spw'`` 

105 produces sufficiently less flagging. If successful, the gain table from this solution interval 

106 is pre-applied before calculating the gains for subsequent solution intervals. 

107 

108 Subsequent solution intervals all use ``combine='spw'`` and ``gaintype='T'``. The second 

109 solution interval is typically ``solint='inf'``, though in the event that a science target has 

110 only a single scan this will be will skipped as it would be almost equivalent to the inf_EB 

111 solution interval, and finish with ``solint='int'``. Between the ``inf`` solint, or ``inf_EB`` 

112 if ``inf`` is not included, and the ``int`` solution intervals, 

113 :func:`~pipeline.hif.cli.hif_selfcal` will attempt solution intervals that split the median 

114 scan time approximately evenly into multiple solution intervals. The task will target a total 

115 of 5 iterations of self-calibration including the inf and int solution intervals, and the 

116 amount that the current solution interval is divided by to reach the next solution interval is 

117 set to reach this maximum number of 5 iterations, with some adjustments to avoid single 

118 integrations from being left out. 

119 

120 The solution intervals are, with the exception of ``inf_EB``, not cumulative. That is to say 

121 that if the solution intervals to attempt are [``inf_EB``, ``inf``, ``int``], the ``inf_EB`` 

122 solutions will be pre-applied when calculating gains for ``inf`` and ``int``, but ``inf`` will 

123 not be pre-applied when calculating ``int``. At the end of self-calibration, only the gain 

124 table from the final successful solution interval, along with the gain table from ``inf_EB`` if 

125 it is not the final successful interval, will be applied. Any successful intermediate steps 

126 will be discarded. 

127 

128 Clean thresholds are set initially as multiples of the rms of the image. The first ``inf_EB`` 

129 solution interval is set by the SNR of the initial image divided by a factor of 15, the final, 

130 int, solution interval is set to clean to a threshold of 5x the rms of the image, and the 

131 thresholds in-between are scaled logarithmically between these two values. While the planned 

132 thresholds for each solution interval are set as multiples of the rms and remain unchanged, the 

133 rms of the images is measured from the "post" image of each solution interval, stored as the 

134 current rms, and multiplied by the planned multiple of the rms for the next solution interval. 

135 

136 **Solution Acceptance/Rejection** 

137  

138 Several criteria are considered when determining whether a given self-calibration solution has 

139 successfully improved the calibration of a science target:  

140  

141 - The beam area in the image made after applying the solutions for the solution interval must 

142 not increase by more than 5% compared with the beam size of the initial image, 

143 pre-self-calibration 

144 - The SNR of the "post" image for the current solution interval (step 3 above) must increase 

145 compared with the SNR of the "pre" image of the current solution interval (step 1 above). 

146 The rms of both "pre" and "post" images are measured outside of the clean mask from the 

147 "post" image so that they are calculated from the same area of the image. 

148 - :func:`~pipeline.hif.cli.hif_selfcal` further requires that the "near-field" SNR must also 

149 increase in the "post" image as compared with the "pre" image. Statistics dubbed with the 

150 moniker "near-field" (or "NF") use an rms measured in a mask that extends from slightly 

151 beyond the clean mask out to a distance several times the largest angular scale beyond that 

152 rather than the rms calculated outside of the clean mask out to the extent of the image. 

153 The intention of this near-field mask is to measure the rms in regions close to the source, 

154 where artifacts are expected to be particularly impactful so that the rms is not washed out 

155 large empty regions of the image. 

156 - Though some amount of flagging due to selfcal can lead to small increases in the rms, large 

157 increases (>5%) in the rms, even with an accompanying increase in the SNR and NF SNR, are 

158 not allowed. 

159  

160 For the ``inf_EB`` solution interval, a slight (<2%) reduction in the SNR and/or the NF SNR is 

161 allowed to enable the routine to go on to additional, shorter solution intervals, though if 

162 this is allowed and then there are no further successful solution intervals, the ``inf_EB`` 

163 solution is later failed.  

164 

165 For mosaics, these statistics are computed and evaluated on the mosaic as a whole, and also for 

166 each individual component field of the mosaic. To avoid the cost of imaging a large number of 

167 sub-fields individually, :func:`~pipeline.hif.cli.hif_selfcal` instead corrects the full-mosaic 

168 image for the primary beam, makes a sub-image of each field, and then applies the single field 

169 primary beam in order to approximate the image that would have been made from an individual 

170 imaging run. In the event that an individual sub-field fails a given solint, the solutions for 

171 the most recent successful solint for that sub-field are re-applied (if available), and the 

172 image of the mosaic as a whole is remade prior to evaluating the success of the mosaic as a 

173 whole. For a selfcal solution interval to be considered successful for a mosaic, the mosaic as 

174 a whole must succeed, and at least one sub-field must also be improved. 

175 

176 **Weblog** 

177 

178 The :func:`~pipeline.hif.cli.hif_selfcal` stage Weblog page shows a summary table describing 

179 the targets considered, the solution intervals to be considered, whether those solution 

180 intervals were actually attempted and/or applied, and whether self-calibration was successful 

181 for that target. For each target, there is then a table showing the initial and final images, 

182 listing statistics for each such as the SNR and rms, along with a brief description of whether 

183 self-calibration was successful, what the final solution interval was, and why self-calibration 

184 was stopped. Then an additional table is provided providing statistics such as the SNR, 

185 improvement of the SNR, RMS, improvement of the RMS, integrated flux within the clean mask, 

186 beam size before and after that solution interval, and whether that solution interval succeeded 

187 or failed (and why it failed) for each solution interval attempted for that source. Clicking on 

188 the "QA Plots" link for each solution interval leads to a separate page showing the before and 

189 after images as well as plots of the gain solutions for each EB and antenna combination. For 

190 mosaics, there is an additional per-field sub page that repeats all of the same information, 

191 but on a field-by-field basis. An example Weblog for the :func:`~pipeline.hif.cli.hif_selfcal` 

192 stage is shown below. 

193

206 

207 Notes: 

208 QA scores: 

209 

210 - QA = 1.0 if self-calibration was not attempted because the estimated SNR is too low. 

211 - QA = 0.99 if attempted but unsuccessful and is therefore not applied. 

212 - QA = 0.98 if successful and applied. 

213 - QA = 0.85 if applied but the RMS got worse for at least one source. 

214 - QA = 0.90 if a new/experimental mode was used. 

215 - QA = N/A for unsupported modes (e.g. ephemeris targets).
